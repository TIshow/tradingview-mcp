### なぜ手選びのリストをやめたか

当初は `scripts/watchlist.json` の61銘柄を使う予定だったが、これは**記事執筆用にテーマ別の代表銘柄を人が選んだもの**であり、研究用ではない。問題は2つあった。

1. **選択バイアス** — 「今も存在する有名な大型株」を選ぶことは、結果的に生き残った企業を選ぶこと
2. **統計的検出力の不足** — 61銘柄×2年 ≒ 3万観測。本研究の最大の制約は「データが増えないこと」なのに、自ら狭めていた

61銘柄という上限は、TradingView が1銘柄5〜10秒かかることから来た制約だった。**データ源が J-Quants（日付指定で全4,446銘柄を1リクエスト取得可能）に変わった時点で、この制約は消滅している。**

**ルールで定義することの効果**
- **選択バイアスが原理的に消える**（人が銘柄を選ばない）
- **生存者バイアスも消える**（日付指定マスタで当時の構成銘柄が取れる。実測確認済み）
- §5 の流動性条件がそのままユニバース定義になり、**新しい閾値を発明していない**
- 観測数が 3万 → 約34万（**約11倍**）

その結果、**「銘柄選択に関する主張の禁止」を解除できる**（§4 参照）。

> 注：`scripts/watchlist.json` の61銘柄は研究ユニバースから外れるが、スキャナや録画デモでは引き続き使用する。

### なぜ ETF/ETN/REIT を外すか（2026-08-14 追記・凍結前）

`universe-jp.json` で `market="その他"` の112銘柄（ETF・ETN・REIT）をユニバースから除外する。理由は2つあり、**どちらも結果を見る前に成立する**。

1. **研究課題が「株式の銘柄選択」だから。** 日経ダブルインバースのようなレバレッジ型・インバース型は構造的な減価を持つ商品で、企業の株式とは別物。同じ断面に並べて順位付けすること自体が課題の定義と噛み合わない。
2. **データ破損がこの層に集中しているから。** 探索期間で1日40%超動いた22件のうち、ETFの4件はすべて「2営業日だけ価格が1/2または1/10になり、元に戻る」往復型の破損だった（`research/data-bias-registry.yaml` の `etf_price_glitches`）。逆張り戦略はこれを最優先で拾う。

**除外範囲の検証（全数確認）**
- `market="その他"` の112銘柄は**すべて**ETF・ETN・貴金属上場信託（純金/純銀信託を含む）で、事業会社は1件も含まれない
- 残る母集団1,081銘柄（プライム936 / スタンダード82 / グロース63）に、非株式は**0件**。J-REIT は母集団に元から含まれていない
- 属性不明の銘柄は0件。属性が取れない銘柄はユニバースに**採用しない**実装にしてある（`universeByDate`）
- 実行のたびに除外件数を表示する。黙って落とさない

除外後、ユニバース内に残る40%超の変動は8件で、すべて実際の値動きだった。**この追記は契約凍結前に行っており、前後の数字は `research/results/` に残してある。**

> ETF はパネル（生データ層）には残してある。将来 TOPIX 連動 ETF を市場リターンの代理変数として使う可能性があるため。ユニバースから外れているので、戦略が保有することは構造的に起こらない。

## 6. 効用関数 U（凍結）

```
U = w1·Return + w2·Sharpe − w3·DD − w4·Turnover + w5·Diversification

w1 = 0.5   w2 = 1.0   w3 = 1.0   w4 = 0.3   w5 = 0.5
```
※ バランス型：Sharpe と ドローダウンを同等に重視する。

- **既存ポートフォリオのバージョン**: `baseline_v1`（§10のベースライン5種）
- **評価指標**: `ΔU = U(既存 + s) − U(既存)`
- **推定誤差の扱い**: 点推定と併せて **95% 信頼区間**を保存。**区間が0を跨ぐ候補は採用しない**
- **同点時の優先順位**: ① 独立性が高い方 ② turnover が低い方 ③ 経済的説明が単純な方

## 7. リスク管理（決定論的コードが強制。LLMは触れない）

| 項目 | 値 |
|---|---|
| 最大DD上限 | **−20%** — ★**実運用の停止ルール**。研究では測定を打ち切らない（下記） |
| 1トレードあたりリスク | **2%** |
| 1銘柄あたり最大比率 | **20%** |

| 空売り | 行わない |

> **最大DDの扱いを明確化する。** 当初「−20%を超えたら停止」としていたが、
> これをバックテスト中に発動させると測定が途中で打ち切られ、戦略を評価できない。
> 実測: **何もしない等ウェイト保有ですら 2018-12 に −20% を超え**、8年の検証が2年で終わった。
> ロングオンリーの株式では −20% 超は通常の下落局面で発生する（探索期間のベンチマーク実測値は **−30.8%**）。
> → **研究では全期間を走らせて最大DDを指標として測り、棄却判定は事後に行う**。
> 「−20%で止める」は実運用（スコープ外）のルールとして残す。

### 9.1 適用範囲は仮説ごとに事前宣言する

日本株と米国株は**構造が違う**（株主優待の有無／単元株100株 vs 1株／参加者構成／取引時間）。
したがって**市場に「発見用・検証用」の役割を固定しない**。片方で再現しなくても、それが「ノイズだった」のか「市場構造が違う」のか区別できないためである。

代わりに、**仮説の登録時に適用市場を宣言する**（`research/registry.schema.yaml` の `market_scope`）：

| scope | 意味 | 判定 |
|---|---|---|
| `both` | 「流動性の高い大型株で成立するはず」など市場非依存の主張 | **両市場で成立を要求（AND）** |
| `jp_only` | 優待権利落ち前の需給など**日本固有**の現象 | 日本株のみで判定。米国は対象外 |
| `us_only` | 1株取引による小口の行動など**米国固有**の現象 | 米国株のみで判定 |

> **禁止**：`both` を宣言した仮説について「日本株**または**米国株のどちらかで通ればOK」とすること。2回試して良い方を採るのは多重検定にあたる。
> **禁止（最重要）**：`both` で登録した仮説が片方で失敗した後、事後に `jp_only` へ**範囲を狭めること**。これは後付けの多重検定である。狭めた版を検証したい場合は**新しい子仮説**として登録し、別データで検証する。
> `scope: both` で片方が成立しなかった場合は `market_dependent` として棄却を記録する。
> 試行数の計上：`both` は1仮説を2市場で検証（2試行）、`jp_only`/`us_only` は1試行。レジストリは市場をまたいで共通。

### 9.2 反証テスト（2026-08-14 追加・凍結前）

統計的な判定に進む前に、**安上がりに落とせるものを先に落とす**。ベースライン5種を実装して実際に走らせた結果から追加した。実装は `scripts/run_baselines.js`。

| テスト | 内容 | 棄却の基準 |
|---|---|---|
| **コスト耐性** | 手数料+スリッページを 1倍 / 2倍 / 4倍 にする | 2倍で消えるなら実運用に耐えない |
| **位相不変性** | 開始日を1〜4営業日ずらす（＝リバランス曜日が変わる） | ベンチマーク自身の振れ幅の3倍を超えたら脆い |
| **ランダム帰無仮説** | ユニバースから毎週でたらめに20銘柄選ぶ試行を40回 | 分布の上位10%に入らないなら情報を持っていない |

**位相不変性について。** リバランスの曜日は戦略の中身と無関係な設定なので、実体のある戦略なら結果は動かないはずである。実測では逆張りが位相を変えるだけで **−18.4%〜+52.6%（振れ幅71pt）** 動いた。当初 86.1% と出ていた数字は「たまたまその曜日だった」以上の意味を持たなかった。

**ランダム帰無仮説について。** 20銘柄しか持たないポートフォリオの成績は、選び方に情報が無くても大きくばらつく。**コスト0（＝銘柄選択そのものの力）と コスト1倍（＝手取り）を分けて見ること。** ランダム選択は毎週全入れ替えで回転率が最大になるため、コスト込みだけで比べると「回転率が低い」というだけの理由でベースラインが勝ってしまい、選択力を測れない。

**プロジェクトの終了条件**: 実験予算の消化 または 封印期間の検証完了
