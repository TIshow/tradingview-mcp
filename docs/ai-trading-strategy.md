# AIトレーディング — 戦略と実験計画

> **一言で**：TradingView MCP を「銘柄を絞り込む道具」ではなく **「AIが相場を判断する実験装置」** として使い、
> *AIの視覚判断・文脈統合はチャート分析に本当に効くのか* を、自己欺瞞なく定量的に検証する。

- **最終更新**: 2026-08-11
- **ステータス**: 戦略確定 / 基盤未構築 / 主要ケイパビリティ3つが未検証
- **関連**: [content-pipeline.md](content-pipeline.md)（記事制作） / [tooling-notes.md](tooling-notes.md)（ツール実務）
- **スコープ外**: 実際の発注・執行。本リポジトリは**研究と検証まで**を扱う。

---

## 1. 立ち位置 — TradingView は「判断エンジン」であって「スクリーニングエンジン」ではない

TradingView MCP は1銘柄ずつチャートを切り替えて読む方式のため、**大量スキャンには向かない**（実測 5〜10秒/銘柄）。

| 銘柄数 | 所要時間（実測ベース） |
|---|---|
| 61銘柄 | 約7分 |
| 500銘柄 | 約1時間 |
| 東証全4,000銘柄 | 7〜11時間（毎日は非現実的） |

価格データを大量取得するだけなら無料の一括API（J-Quants等）が数秒で終わる。**そこにAIもTradingViewも要らない。**

**革新があるのは、絞り込んだ後の「深い判断」の層**である。古典的バックテストは数式で書けるルールしか試せないが、AI×TradingViewは以下ができる。

## 2. アーキテクチャ（ファネル）

```
数千銘柄 ──[一括データ / TVスクリーナーAPI(要検証)]──▶ 数秒 ──▶ 上位100
                                                                  │
上位100 ──[TradingView MCP：視覚判断・リプレイ・文脈統合・描画]──▶ 上位5
                        ↑ ここが本丸。AI×TVでしかできない層
```

- **広く浅く**：外部一括データ、または TradingView 内部スクリーナーAPI（`ui_evaluate` 経由・未検証）
- **狭く深く**：TradingView MCP

---

## 3. AIの3層（＝古典的手法との差分）

| 層 | 内容 | 古典的バックテストで可能か |
|---|---|---|
| **層1 視覚判断** | チャートを"見て"形を読む（トレンドの綺麗さ、保ち合い、支持線の効き方） | ❌ 数式化できない |
| **層2 文脈統合** | ニュース・決算・金融政策・マクロをチャートと結合 | ❌ 価格データしか扱えない |
| **層3 実行** | リプレイで逐次判断／Pine生成・自己検証／チャートへの描画 | ❌ |

**層2は本セッションで既に実証済み**：61銘柄スキャンで「銀行が全行独歩高」を検出 → Web検索で日銀1%利上げ(2026-06-16)・MUFGのトヨタ超え(2026-07-13)・JGB 2.82% を出典付きで取得 → 「金利正常化→利ざや改善→最高益→株価最高値」の因果を構成。数値スキャンだけでは「なぜ今か」は出てこない。

## 4. 検証の鉄則（自己欺瞞を防ぐ）

**これらは探索を始める前に固定する。後から決めると必ず自分に都合よく歪む。**

| 鉄則 | 理由 |
|---|---|
| **① 銘柄ではなくルールを探す** | 銘柄探索は選択バイアスの塊（下記実証）。ルールを全銘柄に等しく適用し、ポートフォリオ全体で評価する。「今日の注目銘柄」は検証済みルールの**出力**として得る |
| **② データを3分割し、封印データは1度だけ触る** | 探索用／調整用／**封印**。封印データで落ちたら捨てる |
| **③ 全試行を自動記録** | 「何通り試したか」が無いと Deflated Sharpe で補正できない |
| **④ 常に単純保有と比較** | 実測でRSI×MACDは全銘柄で単純保有に完敗。ベンチマークを超えられないルールは無価値 |

### 選択バイアスの実証（[scripts/selection_bias_demo.js](../scripts/selection_bias_demo.js)）
**優位性ゼロと分かっているランダムデータ**61銘柄 × 50パラメータ = 3,050試行の結果：

```
Sharpe 1.5以上: 48件
Sharpe 2.0以上:  3件
最強: 銘柄#61  Sharpe 2.15  総リターン +34.6%   ← 全部まぐれ
```

さらに深刻な事実として、**実データのバックテスト結果（+29.5%、+13.9%、−3.8%、+61.0%）はこのノイズ由来の数字と区別がつかない**。だから検証装置が要る。

> 補足：1年の日次データから推定する年率Sharpeの標準誤差は約1.0。**Sharpe 1.5は単発でも統計的に有意ですらない**。また「条件を満たすまで繰り返す」探索の後に順列検定やモンテカルロをかけても、"何回探したか"は補正されない。

## 5. 情報リーク対策 — 「未来の答え」と「世界の仕組み」を分ける

| 種類 | 例 | 検証での扱い | 運用での価値 |
|---|---|---|---|
| **未来の答え**（リーク） | 「2024年のトヨタはこの後上がった」 | ❌ 検証を壊す | ゼロ |
| **世界の仕組み**（文脈知識） | 「利上げ局面では銀行の利ざやが改善」 | ✅ 使ってよい | ⭐ AIの本当の武器 |

**測定の問題であって、AIの能力の否定ではない。** 実運用では未来の答えは存在しないので、リーク問題は消滅し、文脈知識は純粋な上乗せになる。

**クリーン検証期間**：アシスタントの知識カットオフは 2026-01。現在 2026-08。→ **2026年2月〜8月の約7ヶ月は答えを知らないクリーンな期間**。ここでリプレイを回せば、リークなしで層1・層2を測定できる。

補助策：チャートの**銘柄名・日付を隠す**（匿名化）／フォワードテスト（今日以降を記録）。

## 6. 構築するもの（優先順）

| 順 | 構築物 | 中身 | 解決すること |
|---|---|---|---|
| **0** | **ケイパビリティ検証** | 下記§8の未検証3点を先に潰す | 設計の分岐点。ここ次第で計画が変わる |
| **1** | **データ基盤** | 履歴の深掘り（`chart_scroll_to_date`）＋ローカルキャッシュ | 現状 5〜10秒/銘柄 → **ミリ秒**。実験が100倍速くなる |
| **2** | **バックテストエンジン v2** | 複数銘柄同時保有・損切り・ATRサイジング（1トレード◯%リスク）・スリッページ・**保有中DD**・Sharpe/CAGR/アンダーウォーター期間 | 現行は1銘柄・損切なし・全額投入という粗い実装 |
| **3** | **検証ハーネス** | OOS分割／ウォークフォワード／順列検定／モンテカルロ／**Deflated Sharpe**／試行ログ | 「まぐれか本物か」の自動判定。**合否だけ見れば良い**形にする |
| **4** | **特徴量ライブラリ** | モメンタム・ボラ・出来高・相対強度・レンジ位置・季節性等を全銘柄×全日付で事前計算 | パターン発見を規律ある形で可能に |
| **5** | **実験ループ** | ルール案を20〜50個まとめて回し、生き残りを見る | ここで初めて大量実験が安全になる |

**ルールの実体**（エンジンに渡すデータ形式のイメージ）:
```js
{ name:"逆張りRSI・週次入替", rank: bars => rsi(bars,14), order:"asc",
  hold:5, rebalance:"weekly", sizing:"equal", stopLoss:-8 }
```
`rank` を差し替えるだけで無数のバリエーションになる（逆張り／順張り／出来高／相対強度／複合）。
**注意**：ルール生成は無限にできる＝タダなので、**規律なき大量生成は事態を悪化させる**。ボトルネックは生成能力ではなく判定能力。

## 7. インパクトのある実験（TradingViewでしかできないもの）

面白い順。いずれも「誰もクリーンにやっていない」領域。

### ① チャートパターンは本当に機能するのか（定量化）
三角保ち合い・カップウィズハンドル・ヘッドアンドショルダー等は何十年も語られてきたが、**検出に人間の目が必要だったため大規模検証がない**。AIの視覚認識ならスキャンできる。「AIがパターン検出 → その後N日の成績を測定」で、教科書の定説に定量的な答えを出す。

### ② AIが自分でインジケーターを発明する閉ループ
仮説 → **Pineコード生成** → コンパイル → **TradingView自身のストラテジーテスターで検証** → 結果を読んで自己改良 → 反復。`pine_*` + `data_get_strategy_results` が揃うTradingView固有の自律ループ。

### ③ AIは支持線を正しく引けるのか
AIが支持線・抵抗線を判断 → **実際に描画**（`draw_shape`）→ その線が後に効いたかを測定。「AIのライン取りは人間より上手いか」は測定できるようで誰も測っていない。動画映えも強い。

### ④ リプレイ対決：AI vs 数式ルール vs 単純保有
同一期間をリプレイで走らせ、3者に実際に売買させて（`replay_trade`）P&Lを比較。**対照群があるので「AIの判断は本物か」に答えが出る**。コンテンツとしても強い。

### ⑤ 層2は層1を上回るか（本命の学術的問い）
同じチャートを「画像のみ」vs「画像＋当時のニュース」で判断させ、精度差を測定。差が有意なら **「AIだからできる」の定量的証明**になる。point-in-time（その時点で入手可能だった情報のみ使用）の厳守が必須。

### ⑥ マルチタイムフレーム視覚判断
週足・日足・時間足を同時表示（`pane_set_layout`）して総合判断。熟練トレーダーの手法で、最も数式化が難しい領域。

## 9. 実測済みの制約・事実（2026-08時点）

- **スキャン速度**: 5〜10秒/銘柄（61銘柄で約7分）
- **取得可能バー数**: 384〜814本（チャートが読み込んだ範囲のみ。1500本要求しても増えない）→ 深い履歴は `chart_scroll_to_date` で強制ロードが必要
- **指標読み取りは信用不可**: `data_get_study_values`・スクショ凡例は stale。**生バーから自前計算**が唯一の正解（登録EMAとの一致で精度実証済み）
- **`batch_run` は壊れている**うえチャート状態を汚染する
- **銘柄切替の stale 問題**: 切替直後は前銘柄のバーが残る → 「終値が変化するまで待つ」ゲートが必須
- **データは遅延**（`TSE_DLY:`）。日足・終値ベースの分析には支障なし
- **既存戦略の実測**: RSI×MACD（日足ロングのみ）は日本株5銘柄すべてで**単純保有に完敗**（例: 8411 みずほ 戦略−3.8% vs 単純保有+89.1%）。※トレード数12〜24と少なくサンプル不足
