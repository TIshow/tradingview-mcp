## 1. 全体パイプライン（11段）

```
0. 研究契約を定義                  ← 結果を見る前に条件を固定する
   ├─ 対象市場・時間軸・売買容量
   ├─ 予測対象と意思決定対象
   ├─ 利用可能時点（point-in-time）
   ├─ ハード棄却条件 と 効用関数 U（重み込み）
   └─ 完全封印する最終テスト期間
        ↓
1. Point-in-timeデータ基盤
   ├─ 外部API・公式データ
   ├─ 欠損・改定・銘柄変更
   ├─ タイムゾーン・取引時間
   ├─ データとコードのバージョン固定
   └─ Data Bias Registry（汚染を機械可読に記録）
        ↓
2. 判定・反証装置                  ← 生成器より先に完成させる
   ├─ リーク検査 / lookahead / repaint
   ├─ 時系列ウォークフォワード
   ├─ Purge / Embargo
   ├─ 手数料・スプレッド・スリッページ・未約定
   ├─ DSR・PBO・多重検定補正
   └─ 流動性最低条件（v0）／容量・市場インパクト（後）
        ↓
3. ベースライン／既存シグナルライブラリ
   └─ トレンド / 逆張り / ボラティリティ / 出来高・流動性 / クロスアセット
        ↓
4. LLMが仮説を生成し、コード化
   └─ 経済的説明・反証条件・実装・単体/プロパティテスト
        ↓
5. 重複排除
   └─ コード類似性 / シグナル相関 / PnL相関 / 共通因子感応度 / 仮説の系譜
        ↓
6. 自動実験・判定
        ↓
7. 全試行を記録（成功・失敗・エラー・依存関係）
        ↓
8. 既存シグナルに対する増分を評価（ΔU）
        ↓
9. 反証・ストレステスト
        ↓
10. TradingViewで失敗局面を再現・解剖 → 観察は「新しい子仮説」として登録
        ↓
11. Shadow → Paper → 極小ロット      ← 本リポジトリのスコープ外（人間の領域）
```

## 2. Step 0：研究契約（最初の成果物）

**最初に作るのは戦略ではなく、結果を見る前に条件を固定した契約書**である。
テンプレート：[`research/CONTRACT.template.md`](../research/CONTRACT.template.md)

固定する項目：
- 対象市場・時間軸・ユニバース定義
- 予測対象（何を予測するか）と意思決定対象（何を決めるか）
- **ハード棄却条件**（下記§3）
- **効用関数 U の式と重み**
- 既存ポートフォリオのバージョン
- 推定誤差の扱い・同点時の優先順位
- **封印期間**とアクセス予算
- 実験予算（仮説族ごとの上限）

> **なぜ先に固定するか**：判定基準を後から決めると、その基準自体が結果に適合する。U を後から決めれば、U が候補を通すように歪む。

---

## 3. 判定：ハード条件 → 増分効用の2段構え

**単一スコアに平均化しない。** 重大な欠陥が他の高得点で薄まるのを防ぐ。

### ① ハード棄却条件（1つでも該当したら即棄却）
- lookahead / repaint がない
- Pine実装とPython/JS実装が一致している
- OOSでコスト控除後にプラス
- 最大DDが上限以内
- 最低取引数を満たす
- 流動性最低条件を満たす（§5）
- Data Bias Registry の `forbidden_claims` に抵触していない

### ② 通過後のみ、増分効用 ΔU を評価
```
ΔU = U(既存ポートフォリオ + s) − U(既存ポートフォリオ)

U = w1·Return + w2·Sharpe − w3·DD − w4·Turnover + w5·Diversification
```
重みは Step 0 で固定。**点推定だけでなく信頼区間も保存する。**

### ③ 出力は合否ではなく「証拠プロファイル」
```
統計的証拠     0.72
経済的合理性   0.61
コスト耐性     0.83
独立性         0.34
レジーム耐性   0.76
容量適合性     0.91
```
単体では不合格でも、**既存が負ける局面で稼ぐなら価値がある**。二値判定はこの情報を捨てる。

### 見るべき増分
既存シグナル除去後の予測力 / ポートフォリオSharpeの増加 / DDの減少 / テールリスク低減 / レジーム補完性 / turnover増によるコスト / 既存とのPnL相関 / Failure Atlas に対する新情報

> 単体Sharpe 0.7でも既存が負ける時に稼ぐなら価値がある。単体Sharpe 2.0でも既存モメンタムの複製なら追加価値は小さい。

## 4. Data Bias Registry — 汚染を機械可読にする

完全な point-in-time は無料データでは困難。**達成を目指すのではなく、汚染箇所を測定・記録し、結論の射程を機械的に制限する。**

テンプレート：[`research/data-bias-registry.template.yaml`](../research/data-bias-registry.template.yaml)

```yaml
dataset_id: equity_daily_v1
price_point_in_time: true
corporate_actions_point_in_time: unknown
universe_survivorship_free: false
fundamentals_as_reported: false
announcement_timestamp_quality: unavailable
allowed_claims:
  - fixed-universe price-pattern research
forbidden_claims:
  - historical stock-selection performance
  - fundamental announcement reaction
```

**判定装置は、汚染されたデータで `forbidden_claims` に該当する結論を出した実験を自動棄却する。**

> 「知らずに汚染される」と「汚染を知った上で射程を狭める」は全く別物。

---

## 5. 流動性の最低条件（v0から入れる）

厳密なマーケットインパクトモデルは候補が出てからでよいが、**流動性を完全に無視すると実行不能な戦略を研究し続ける**。v0では簡易条件のみ：

- 最低売買代金
- 最大スプレッド
- 最大回転率
- 約定価格に保守的なスリッページ
- 仮想注文額 ÷ 日次売買代金

---

## 6. 封印期間の管理 — 「見た回数」を予算化する

boolean では足りない。

```yaml
sealed_test:
  dataset_hash: "..."
  status: untouched          # untouched | touched | invalidated
  access_count: 0
  access_reason: null
  accessed_at: null
  invalidated_for_future_research: false
```

**一度見た後に戦略を修正したら、その期間は以後の仮説にとって封印期間ではない。** 新しい期間を用意するか、Shadowデータが蓄積するまで待つ。

## 7. 実験レジストリ — 失敗を失わない台帳

スキーマ：[`research/registry.schema.yaml`](../research/registry.schema.yaml)

```yaml
experiment_id:
parent_hypothesis_id:      # 仮説の系譜
timestamp:
llm_model:
prompt_hash:
code_hash:
data_version:
feature_version:
market_universe:
training_period:
validation_period:
parameters_tested:
execution_assumptions:
result:
rejection_reason:
signal_cluster:
sealed_test_touched: false
```

### 棄却理由の分類（LLMへの学習信号になる）
統計的に弱い / コストで消滅 / 既存戦略と重複 / 特定期間に依存 / 特定銘柄に依存 / 実装不一致 / データリーク / 容量不足 / 経済的説明が成立しない

**成功例だけ保存すると DSR・PBO が正しく計算できず、LLMも同じ失敗を繰り返す。**

## 8. 仮説の系譜（lineage）— 「1000個」は1000回の独立実験ではない

EMA期間だけ違う／RSI閾値だけ違う／同じモメンタムの別表現／同じプロンプトの言い換え——これらは独立仮説ではない。

```
1000生成
  ↓ コード重複除去
310
  ↓ シグナル相関クラスタ
120
  ↓ 潜在因子
25
  ↓
8つの本質的に異なる仮説族
```

記録すべきは試行数だけでなく：**親仮説 / 派生方法 / 変更パラメータ / シグナル相関 / PnL相関 / 共通エクスポージャー**。

---

## 9. 実験予算管理

予算がなければ、LLMは同じアイデアを微調整し続け、**必ず偶然の勝者を見つける**。

```
仮説族A：最大100試行
仮説族B：最大50試行
パラメータ変種：各仮説最大20
最終テスト：プロジェクトにつき1回
```

## 10. TradingView顕微鏡の使い方 — 解剖は「新しい実験」

失敗チャートを見れば、**後知恵で説明はいくらでも作れる**。

```
実験Aが失敗
    ↓
TradingViewで原因候補を観察
    ↓
新仮説B として登録（lineageに追加）
    ↓
別期間・別銘柄で検証
```

**TradingViewで得た説明を、実験Aの成功理由として後付けしない。** 必ず子仮説として登録し、独立に検証する。

用途：バックテスター間の不一致調査 / 異常トレードの視覚確認 / Pineのrepaint調査 / バー内約定仮定の確認 / 失敗局面のパターン発見 / 次の反証仮説の生成

> **判定装置＝裁判所、TradingView＝現場検証・顕微鏡。**

## 11. v0 — 最小構成で全工程を貫通させる

11段を全部作ってから統合するのが最大の失敗パターン。**まず小さく一周させる。**

| 段 | v0の構成 |
|---|---|
| 0 研究契約 | 1ページ。対象・期間・U・ハード条件・封印期間を固定 |
| 1 データ | 1ソース・50〜100銘柄・日足。**Data Bias Registry を必ず作る** |
| 2 判定装置 | OOS＋ウォークフォワード＋DSR＋コスト＋流動性条件（**PBOは次段階**） |
| 3 ベースライン | 5個（トレンド／逆張り／ボラ／出来高／相対強度） |
| 4 仮説生成 | **20個**（1000ではない） |
| 5 重複排除 | シグナル相関 ＋ 完全同一シグナル率 |
| 6-7 実験・記録 | §7のスキーマで全件記録 |
| 8 増分評価 | 残差化後の予測力 **と** ポートフォリオΔU の両方 |
| 9 反証 | **コスト 1倍・2倍・4倍の3点**（崩壊点が見える）／期間変更は実験前に固定 |
| 10 顕微鏡 | 失敗1件を解剖 → **観察を新規仮説として登録** |
| 11 受け渡し | decision packet の**形式だけ定義**（実運用はリポジトリ外） |

### v0の完成条件 — **利益の出る戦略を見つけることではない**

- [ ] 20仮説が同一パイプラインを完走する
- [ ] エラー・棄却も含めて全件記録される
- [ ] 同じ入力で同じ結果を再現できる
- [ ] 封印期間へ不正アクセスできない
- [ ] 重複仮説を検出できる
- [ ] DSRが**全試行数**を参照して計算される
- [ ] TradingView観察から新仮説の lineage を作れる
- [ ] **生き残りゼロでも正常終了する**

> 最後の条件が特に重要。**全候補棄却はシステムの失敗ではなく、判定装置が機能した結果**である。

## 11.5 市場の扱い — 役割を固定せず、仮説ごとに範囲を宣言する

日本株と米国株は**構造が違う**：株主優待の有無／単元株100株 vs 1株／参加者構成／取引時間の制度変更。

そのため「一方を発見用、他方を検証用」と役割を固定しない。**片方で再現しなくても、「ノイズだった」のか「市場構造が違う」のか区別できず、検証として機能しない**（交換可能性が成り立たない）。

代わりに、**仮説の登録時に適用市場を宣言する**：

| scope | 意味 | 判定 |
|---|---|---|
| `both` | 市場非依存の主張（例: 流動性の高い大型株で成立する） | **両市場で成立を要求（AND）** |
| `jp_only` | 日本固有（例: 優待権利落ち前の需給） | 日本株のみで判定 |
| `us_only` | 米国固有（例: 1株取引による小口の行動） | 米国株のみで判定 |

### 禁止事項
- `both` について「**どちらかで通ればOK**」とすること（2回試して良い方を採る＝多重検定）
- **`both` で失敗した後、事後に `jp_only` へ範囲を狭めること**（後付けの多重検定）
  → 狭めた版は**新しい子仮説**として登録し、別データで検証する

### 受け入れ基準④「別の市場でも残るか」は誰が担うか
役割固定をやめた分、以下が担う：
1. **`scope: both` の仮説** — 事前宣言されていれば正当な複製検証になる
2. **封印期間**（両市場に設定・各1回）— 主たるホールドアウト
3. **フォワード記録** — 本命。時間が経つほど、両市場の真に独立な検証になる

### 制度変更はレジーム断絶として扱う
取引時間の拡大などの制度変更は**構造的断絶**である。前後のデータを素朴にプールすると、変化を「戦略の劣化」と誤読する。
→ Data Bias Registry に**レジーム境界**として日付を記録し、またぐ検証には注記を必須とする。

## 12. フォワード記録（人工投資家）— v0と並行して即座に開始する

### なぜ最優先で始めるか
これまで戦ってきた汚染（生存者バイアス／point-in-time／知識カットオフ／多重検定）は、すべて**過去を後から見る**ことに由来する。**未来に向けて記録すれば、定義上アウトオブサンプル**であり、汚染は構造的に消える。

さらに §1.5-③ で「データが増えないこと」が最大の制約と結論したが、**フォワード記録は毎日1件、汚染ゼロの観測を増やす唯一の経路**である。

> **汚染のないデータは実時間でしか貯まらない。記録開始を遅らせた分は、永久に取り返せない。**

→ **研究契約（§2）を凍結したら、判定装置の完成を待たずに最小構成を走らせる。**
記録さえ正しければ、判定は後からいつでもかけられる。

```
研究契約を凍結
      ↓ 即
最小構成の人工投資家を毎日実行  ← clean data が貯まり始める
      ↓ 並行して
判定装置・レジストリ・データ基盤を構築
```

### 最小構成
1. 毎日、**決まった時刻**にシグナルを出す
2. **後から書き換えられない形**で保存する
3. **手数料・スリッページ込み**で成績を計算する
4. **ベンチマーク**（単純保有・指数）と比較する
5. 負けた局面の原因候補をLLMに挙げさせる（※下記の規律を守ること）
6. 週次で観測日誌を出す

### 規律1：不変性には外部の証人が要る
| 手段 | 強度 |
|---|---|
| ローカルファイル | ✗ 書き換え自由 |
| git commit のみ | △ 履歴を書き換えられる |
| **GitHubへ push**（サーバ側タイムスタンプ） | ○ |
| **寄り前の公開投稿** | ◎ 最強かつ最も安い |

**公開は宣伝ではなく統制装置。** 公開していれば、負けている戦略を黙って消せない。「勝ったものだけ残す」バイアスへの実効的な歯止めになる。

### 規律2：戦略集合を記録開始時に固定する
20戦略を走らせて後から最良を紹介するのは、**過去でやったのと同じ罪**（多重検定）。
- 記録開始時に戦略集合を固定し、**以後は毎回すべてを報告する**
- 途中で追加するなら追加日を記録し、**追加分は別集計**にする

### 規律3：負けた理由の説明は「結論」ではなく「子仮説」
**LLMは負けた後なら、いくらでももっともらしい説明を作れる。** 週次レポートが「洞察に見える作り話」になる典型的な失敗経路。

```
week N   : 負けた → LLMが原因候補を挙げる → 仮説として登録（検証はまだ）
week N+k : その仮説が正しかったかを、以後のデータで判定
```

レポートには「原因はこうだった」ではなく **「原因の候補はこれで、まだ検証されていない」** と書く。
`derivation: autopsy_child` としてレジストリに登録し、独立に検証する（§10と同じ規律）。

### 期待値を正直に宣言しておく
年間の観測は約250件。**穏当な優位性の統計的検出には数年かかる。**
→ **1年目の成果は「市場に勝ったか」ではなく「汚染のない記録が存在すること」。**
ここを最初に宣言しないと、3ヶ月目に「効果が見えない」と感じて失速する。

### 観測日誌（週次レポート）の書式
検証済みと未検証を**必ず分ける**：
- 今週のシグナルと結果（全戦略・例外なく）
- コスト込みの成績とベンチマーク比較
- **検証済みの事実**（記録から直接読めること）
- **未検証の仮説**（原因候補。子仮説IDつき）
- 過去に立てた仮説の検証状況

### スコープ境界
記録・分析・公開まで。**執行と資金運用は本リポジトリの外**（人間の領域）。
教育・分析目的のコンテンツとし、投資助言にはしない。

## 実装の優先順位

1. **研究契約テンプレート**
2. **フォワード記録の開始**（契約凍結の直後。判定装置を待たない）
3. **実験レジストリと sealed-test 制御**
4. v0マイルストーン
5. 判定装置
6. 20仮説の生成

**最初の成果物は戦略ではなく、「結果を見ずに条件を固定できる研究契約」と「失敗を失わない実験台帳」。**
