# 投資家向けコンテンツ制作パイプライン

> **目的**：TradingView MCP を土台に、「投資家が読む理由のあるテーマ・銘柄」を発見し、**再現可能な手順**でテクニカル分析し、投資家向け記事にする。
> 「AIがTradingViewを操作すること」自体は目的ではなく演出。主役は**プロセスの正しさと透明性**。

- **最終更新**: 2026-07-25
- **ステータス**: 設計確定 / ステップ2〜4は構築・検証済み、ステップ1（テーマ発見）と記事組み立ては未構築
- **関連**: 実務メモは [tooling-notes.md](tooling-notes.md)

---

## 1. 全体ワークフロー

```
テーマ・銘柄の発見（ニュース・決算・政策・需給・セクター動向）
        ↓
一次スクリーニング（OHLCVからローカル計算・同一条件）
        ↓
TradingViewによる詳細テクニカル分析（上位3〜5社）
        ↓
投資家向け記事（材料×チャート・強気/弱気の両シナリオ）
```

**3つの分離を守る**
| 工程 | ソース |
|---|---|
| テーマ選定 | ニュース、決算、政策、金利・為替、需給、セクター動向 |
| テクニカル分析 | TradingView の価格・出来高・チャート＋ローカル計算 |
| 記事化 | 材料とチャートを結び、強気・弱気の両シナリオ＋無効化条件 |

**原則**：テーマは**銘柄名ではなく「投資家が知りたい問い」**として定義する。
- ✗ 「AI関連株」（広すぎ）
- ✓ 「半導体装置株の調整は"中間押し目"か"天井"か」「決算後に急落した優良株は反発局面に入ったか」「銀行株は金利上昇を織り込み済みか」

## 2. ステップ詳細

### Step 1｜テーマ発見（＝問い）  ⚠️ 最重要かつ最も未整備
毎日/毎週、以下から候補テーマを3つ程度抽出：
- 決算発表・業績修正 / 政策・規制・金利・為替 / セクター動向 / 価格急変・出来高急増 / 指数採用・M&A・自社株買い / 市場予想との乖離

**ハルシネーション対策（必須）**：投資家向け記事で「事実でない催材」は最悪の事故。
- テーマの根拠は必ず**出典付き・日付付きの一次情報に接地**する（Web検索等）。
- 材料が確認できないときは正直に「明確な催材なし（需給主導の可能性）」と書く。捏造しない。
- 「価格急変・出来高急増」は**テーマではなく"手がかり"**。必ず背後の催材を探しに行く。

### Step 2｜母集団と最低条件（固定）
1テーマにつき10〜30社を用意し、**最低条件を先に明文化**（時価総額・流動性・上場市場など）。
→ **後から都合のよい銘柄だけ選ばない**。ここが知的誠実さの要。

### Step 3｜一次スクリーニング（ローカル計算・同一条件）
全銘柄を画面で1社ずつ読む必要はない。OHLCVから機械的に計算し上位3〜5社へ：
- RSI / MACD・ヒストグラム / 出来高÷平均出来高 / 20日・60日リターン / 指数（日経225・TOPIX・セクター指数）に対する相対強度 / 直近高値・安値からの距離 / 移動平均線の位置関係 / ATR（値動きの大きさ）

**スクリーン・モードは1本に固定しない**（問いに応じて選ぶ）。同一の計算式は全銘柄に等しく適用する。
| モード | 使う問い | 重視する指標 |
|---|---|---|
| **順張り型** | 上昇は再加速するか | モメンタム・相対強度・ブレイク接近度 |
| **逆張り/反発型** | 急落後の反発に入ったか | RSI売られすぎ反転・出来高・支持線接近 |
| **ローテーション型** | 資金はどこへ回るか | 相対強弱×モメンタム（RRG） |

> 注意：モメンタム・相対強度・ブレイク接近度は相関が高く、単純加点は「伸びきった銘柄」に偏る（モメンタムの三重カウント）。重みは問いに合わせて調整し、スコアは**編集上のヒューリスティックであり検証済みの客観指標ではない**と明記する。

参考の順張り型ルーブリック例（v1・要検証）：モメンタム30 / 出来高20 / 相対強度20 / ブレイク接近15 / リスク・値幅15。

### Step 4｜TradingViewによる詳細分析（上位3〜5社）
**TradingViewの役割 = 視覚確認・支持抵抗の描画・記事用スクショ。指標の数値は読まない。**
理由：TV上のRSI/MACD読み取り（`study_values`・スクショ凡例）は stale で不正確（[tooling-notes.md](tooling-notes.md)参照）。**数値の真値はローカル計算**（唯一信頼できるEMA登録値で精度検証済み）。

手順：銘柄切替 → 日足・週足確認 → OHLCV取得 → 高値/安値・支持線/抵抗線の特定 → 必要なら描画 → スクショ → 強気/中立/弱気に分類。

**固定フォーマットで返す**（銘柄間比較と品質安定のため。具体的な価格・数値を必ず入れる）：
```
トレンド:
モメンタム:
出来高:
支持線:
抵抗線:
強気シナリオ:
弱気シナリオ:
見方が無効になる条件:      ← 最重要（分析と占いを分ける）
テクニカル評価: 強気/中立/弱気   ← 「買い/売り」にはしない（助言回避）
```

### Step 5｜記事化
1. なぜ今、このテーマなのか
2. 対象銘柄と選定条件
3. 市場全体・セクターの状況
4. 注目3銘柄のチャート分析
5. 強気／弱気シナリオと重要価格
6. 最も注目する銘柄と理由
7. リスクと今後確認すべき材料

タイトル例：
- 「半導体装置株の調整は"中間押し目"か"天井"か。5社を出来高・RSI・MACDで検証」
- 「決算後に売られた米国株をAIでスキャン。反発初動が見える3銘柄」

## 2.5 発見ステージの設計（2026-07-25 確定）
分析の"手前"＝発見が企画の勝敗を分ける。ここを2エンジンの合流として設計する。

**確定した方針**
- 発見エンジンは2つ（**トップダウン**＝テーマ/催材、**ボトムアップ**＝"面白いチャート"）を**ハイブリッド合流**。
- 広スキャンは **TradingViewのみ・小さめ母集団（60〜80銘柄）**。1銘柄ずつ切替（〜5–10秒/銘柄）の制約に合わせる。数百規模が必要になったら「外部一括データ（Yahoo/stooq）で広スキャン→上位だけTVで視覚確認」を将来オプションに。
- ボトムアップは**リード（手がかり）生成役**。記事化には必ずトップダウンの**催材（出典・日付付き）**を合流させる。催材が無ければ落とすか「純テクニカル」と明示（Step 1のハルシネーション対策と同じ）。

**フロー**
```
[0] マスター・ウォッチリスト（60〜80・テーマタグ付き）  ← 要構築
     ├─(ボトムアップ) テクニカル・スキャナ → "面白いチャート"候補＋シグナルタグ
     └─(トップダウン) ニュース/決算/政策 + RRG(テーマ単位) → "熱い問い/催材"
     ▼ [triage] チャート候補 ↔ 催材 → (銘柄,設定,催材,問い) を記事価値でランク
     ▼ 1つ選定 →【既存パイプライン】母集団スキャン→上位3→TV分析→記事
```

**[0] マスター・ウォッチリスト**（編集可能なconfigとして構築）：スキャン母集団かつテーマ分類。ドラフト（各テーマ5〜8銘柄・計〜70）＝半導体/SPE・AI/電子部品・防衛・銀行/金融・商社・自動車・ゲーム/エンタメ・医薬・小売/インバウンド・海運・通信。

**[1] ボトムアップ・スキャナ**（`analyze_semi_jp.js` を汎用化）：生バーから"面白さ"シグナルを計算し、発火タグ付きで上位を surface。
| シグナル | 記事の型（スクリーン・モードに接続） |
|---|---|
| 出来高急増（today/avg20 ≥ 2–3x） | 材料探索 |
| 52週高値ブレイク/新高値 | 順張り |
| 52週安値割れ/新安値 | ブレイクダウン/警戒 |
| 窓（ギャップ）大 | 決算ギャップ |
| ゴールデン/デッドクロス(50/200) | トレンド転換 |
| RSIダイバージェンス | 逆張り初動 |
| 売られすぎ反転(RSI<30→上向) | 逆張り |
| 相対強弱の極値（対指数/RRG角） | ローテーション |

**[2] トップダウン**：RRG（テーマ単位のローテーション）＋Web検索で催材（出典・日付）。
**[3] triage合流**：面白いチャート ↔ 催材 を突き合わせ、(銘柄,設定,催材,問い) を記事価値でランク→1つ選定→既存パイプラインへ。

**カデンス（二層）**：日次＝「今日の面白いチャート5選」リーダーボード（軽量・動画映え）／週次＝1つ深掘り記事。

## 3. 差別化 — "検証可能なプロセス"を前面に
「AIが予想した」でも「AIが操作した」でもなく、次の3層で信頼と視覚の堀を作る：
1. **同一条件スキャン**（都合よく選ばない規律）
2. **全数値が生バーから自前計算・検算可能**（透明性＝信頼の堀）
3. **RRG等のプロ級ビジュアル**（視覚の堀）

「AIが操作」は動画演出（銘柄が自動で切り替わる絵）として有効だが、主役はプロセスの正しさ。

## 4. バックテストの扱い
- 記事ごとには行わない。**明確な売買ルールの検証企画**にのみ用いる。
  - 良い例：RSI反発＋MACDクロスは大型テックで有効だったか / 決算ギャップ後の押し目買い / 52週高値ブレイク5年検証
  - 悪い例：今の注目3銘柄に後付けルールを当て勝率だけ載せる
- 掲載時は**トレード数・総リターン・PF・最大DD・単純保有との比較**を必須。
- **トレード数を必ず明記**し、少数サンプル（例：数銘柄×400本）から断定しない。
- 実装：[backtest_rsi_macd.js](../scripts/backtest_rsi_macd.js)（既にPF/DD/勝率/buy&hold出力）。

---

## 5. 無料プラン運用（役割分担）
インジケーター2枠制限のため役割を分ける：
- **大量スキャン**：OHLCVからローカル計算（真値）
- **視覚確認・記事画像**：TradingViewのチャート＋重要価格の描画＋スクショ（数値は読まない）
- **EMA枠**：登録済みEMA50/200は精度照合の基準として温存
- **バックテスト**：ローカル計算、または必要時のみ一時的に指標を外してPine戦略

---

## 6. コンプライアンス
- 教育・分析目的のコンテンツ。**特定銘柄の売買推奨はしない**。個別化された投資助言もしない。
- 強気/弱気の両シナリオ＋無効化条件で提示。総合判定は「テクニカル評価（強気/中立/弱気）」に留める。
- 全記事・全ビジュアルに免責を付す。データは遅延（日足終値ベース）である旨を明記。

---

## 7. 再現性と検証可能性
- **再現性＝結果ではなくメソッドの再現性**（データは遅延かつ日々変化）。
- 記事ごとに**基準日を固定し、使った生OHLCVスナップショットを保存**（JSON）。後から誰でも検算できる状態にする＝信頼の堀。
- 精度検証の型：ローカル計算EMA vs チャート登録EMAの照合、生バーのダンプ（[tooling-notes.md](tooling-notes.md)）。
