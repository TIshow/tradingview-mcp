# 研究所憲章 — AI時代の定量投資研究インフラ

> **立脚点**：AIを「予言モデル」ではなく、**仮説生成・実装・反証を人間の研究者100人分の速度で回す研究インフラ**として使う。
> 優位性は「最高のモデル」ではなく、**仮説から反証までの科学的サイクルを、他者より速く・厳密に回すシステム**にある。

## 0. 組織の構成（何が何を担当するか）

| 部門 | 担当 | 実体 |
|---|---|---|
| **研究者・実装者・批判者** | 仮説生成、コード実装、破壊実験の設計 | **LLM** |
| **観測装置（顕微鏡）** | 失敗局面の再現、視覚確認、Pine試作 | **TradingView MCP** |

| **リスク管理** | 制限の強制 | ハードコード（**AIから独立**） |

## 1. 中核原則（設計の背骨）

| # | 原則 | 理由 |
|---|---|---|
| **①** | **LLMは数値を答えない。決定論的プログラムを書く。** 結果はファイルに残す | 同じ入力で答えが揺れる／数値計算は専用手法に劣る／根拠を管理できない、という弱点が構造的に消える。成果物がコードと結果ファイルになり、後から誰でも再実行・検算できる |
| **②** | **判定装置を生成器より先に作る** | 優位性ゼロのデータでも3,050試行でSharpe 2.15が出る（§6で実証）。**生成能力が上がるほど、判定装置がないことの害が大きくなる** |
| **③** | **シグナルは独立ではない。相関を圧縮して独立因子にする** | RSI・MACD・EMAは同じ価格系列の変換。3票ではなく1票。過去のスコアリング設計はモメンタムを三重カウントしていた |
| **④** | **新候補は「既存モデルに対する増分情報量」だけで評価する** | 実装は直交化：既存シグナルで回帰し、**残差に予測力が残るか**を見る。ほとんどの「新指標」はここで死ぬ |
| **⑤** | **銘柄ではなくルールを探す** | 銘柄探索は選択バイアスの塊（§6）。「今日の注目銘柄」は検証済みルールの**出力**として得る |

## 2. 役割分担 — LLMにさせること／させないこと

LLMをそのまま次足予測器にはしない。

| 役割 | 担当 |
|---|---|
| **研究者・プログラマー・批判者** | **LLM** |
| 予測 | 時系列モデル／統計手法（決定論的コード） |
| 有意性判定 | 統計エンジン（決定論的コード） |
| ポートフォリオ構築 | 最適化器 |
| リスク管理 | ハードコードされたルール（AIから独立） |

**LLMの出力は「予測」ではなく「コード」**。これが①の具体形。

## 3. AIの6層

| 層 | AIの役割 |
|---|---|
| **データ** | 欠損・異常値・時刻ずれ・銘柄変更・価格改定の検出 |
| **仮説** | 数学・物理・情報理論・行動科学から候補を生成 |
| **実装** | 仮説を JS/Python/Pine ＋テストコードへ変換 |
| **反証** | コスト増・遅延・期間変更・市場変更などの破壊実験を生成 |
| **メタモデル** | 各モデルが「いつ壊れるか」を予測 |
| **研究組織** | 過去の失敗・類似実験・重複研究を検索して返す |

## 4. 受け入れ基準 — 候補はこの4問を通らないと採用しない

1. **何回再現したか**
2. **既存シグナルを除いても残るか**（＝増分情報量 → 直交化）
3. **コストを倍にしても残るか**
4. **別の市場・時代でも残るか**

これをハーネスの合否条件として**コードに埋め込む**。「AIがすごい予測をした」は評価対象ではない。

### 判定に使う統計手法（詳細は [references.md](references.md)）
| 目的 | 手法 |
|---|---|
| 多数モデルの中の最良が偶然でないか | **White's Reality Check** / **Hansen's SPA test** |
| 試行回数を織り込んだSharpe | **Deflated Sharpe Ratio**（Bailey & López de Prado） |
| 有意水準 | 多重検定下では **t > 3.0** を目安（Harvey, Liu & Zhu） |
| 時系列CVのリーク防止 | **Purged k-fold CV / embargo**（López de Prado） |
| 再標本化 | **stationary bootstrap**（Politis & Romano） |

**独自の判定基準を発明しない。** 先行研究に接地させる。

## 4.5 研究プロトコル（1つの仮説がたどる経路）

```
① 仮説を登録        research/hypotheses/<id>/spec.md
                    何を、なぜ、どの先行研究に基づくか
        ↓
② LLMが実装         research/hypotheses/<id>/strategy.js + test.js
                    ※LLMは数値を答えない。コードを書くだけ
        ↓
③ 探索データで実行   結果は research/results/<id>.json（決定論的・再実行可能）
        ↓
④ 試行を記録        research/registry.json に必ず追記（棄却されたものも）
        ↓
⑤ 反証実験          コスト2倍 / 遅延追加 / 期間変更 / 市場変更
        ↓
⑥ 増分情報量        既存因子で直交化 → 残差に力が残るか
        ↓
⑦ 統計判定          Reality Check / SPA / Deflated Sharpe（試行回数を入力）
        ↓
⑧ 封印データで1回   ここで落ちたら捨てる。再挑戦しない
        ↓
⑨ 失敗の解剖        TradingView顕微鏡で失敗局面を再現 → Failure Atlas へ
```

**棄却された仮説も必ず記録する。** 「効かないと分かっている」ことが資産になる。

## 5. TradingView MCP の位置づけ＝**顕微鏡**

アルファ源でも本番データベースでも執行装置でもない。**統計的異常を人間とAIが観察・再現するための観測装置**。

- AIがPine戦略を生成 → 自動コンパイル → エラー自己修正
- 同じロジックを独立実装し、**Strategy Testerと独立バックテスターを照合**（実装バグの検出）
- 問題のある期間へチャートを自動移動
- **失敗トレードの前後をスクリーンショット化**
- 上位足・関連市場・指標値を同じ時点で収集
- **Replayで過去時点を再現**し、人間が異常ケースを視覚確認

※スキャン速度は5〜10秒/銘柄（全4,000銘柄で7〜11時間）。**大量スキャンには不適**。広く浅くは外部一括データ、狭く深くはTradingView。

## 6. 検証の鉄則（実証つき）

### 選択バイアスの実証 — [scripts/selection_bias_demo.js](../scripts/selection_bias_demo.js)
**優位性ゼロと分かっているランダムデータ**61銘柄 × 50パラメータ = 3,050試行：

```
Sharpe 1.5以上: 48件
最強: 銘柄#61  Sharpe 2.15  総リターン +34.6%   ← 全部まぐれ
```

さらに深刻な事実：**実データのバックテスト結果（+29.5%, +13.9%, −3.8%, +61.0%）はこのノイズ由来の数字と区別がつかない**。

> 1年の日次データから推定する年率Sharpeの標準誤差は約1.0 → **Sharpe 1.5は単発でも有意ですらない**。
> 「条件を満たすまで繰り返す」探索の後に順列検定やモンテカルロをかけても、**"何回探したか"は補正されない**。

### 運用ルール
- **データを3分割**（探索／調整／**封印**）。封印は最後に1度だけ触り、落ちたら捨てる
- **全試行を自動記録**（Deflated Sharpe の入力）
- **常に単純保有と比較**（実測でRSI×MACDは日本株5銘柄すべてで単純保有に完敗）

## 7. 構築順（順序を守ること自体が設計）

```
0. データ基盤（キャッシュ＋履歴の深掘り）        ← 全ての前提。実験が100倍速くなる
1. 検証ハーネス（判定装置）                      ← 生成器より先。ここが背骨
      OOS分割 / ウォークフォワード / 順列検定 / MC
      Deflated Sharpe / 試行レジストリ / §4の4問
2. 戦略ジェネレータ（100個の単純戦略）           ← LLMはコードを書く。数値は出さない
3. 相関クラスタリング → 5〜10の独立因子へ圧縮
4. 残差の保存（毎バー・全モデル）
5. 増分情報量での評価（既存で直交化 → 残差に力が残るか）
6. 誤差相関の監視（全モデルが同時に壊れる局面の検出）
7. TradingView顕微鏡（失敗局面の自動再現）
```

### Model Residual Atlas（4〜6の到達点）
「**どんな条件で、現在の全モデルが系統的に間違えるか**」の地図。
モデルが一斉に失敗したとき、「トレンドが効かない」で終わらせず、以下まで調べる：
- 同じ潜在因子を重複カウントしていないか
- 約定コストの上昇を見落としていないか
- クロスアセットの情報伝播が逆転していないか
- データ生成過程に変化が起きたか
- **モデルのエラー同士が突然相関し始めたか**

## 8. リポジトリ構造（①を強制する形）

```
research/
  hypotheses/     仮説の仕様 ＋ LLMが生成したコード
  results/        決定論的な実行結果（再実行で再現可能）
  registry.json   全試行のログ（多重検定補正の入力・重複研究の検出）
data/
  <code>.json     OHLCVキャッシュ
```

LLMの成果物がコードとして残るため、後から検算も再実行もできる。

## 9. 制約（正直に）

| 制約 | 内容 |
|---|---|
| **データ量が上限を決める** | 日足61銘柄×400〜814本。「全モデルが同時に壊れる条件」を見るにはレジーム転換の回数が足りない。方法論は正しく実装できるが、**結論の強さはデータ量で頭打ち**。中期的には銘柄数の拡大か時間足への降下が要る |
| **残差分析にはベースモデルが要る** | まず素朴なベースモデル（市場ベータ＋モメンタム程度）を置き、**その残差**を対象にする。「全モデルの残差」を名乗るのはモデルが5〜10個揃ってから |
| **誤差相関は今でも測れる** | レジームのラベル付けなしでも、**毎バーの予測誤差を保存して相関行列を時系列で見る**だけで実行可能 |

### 実測済みのツール制約（2026-08時点）
- 指標読み取り（`data_get_study_values`・スクショ凡例）は **stale で信用不可** → 生バーから自前計算（登録EMAとの一致で精度実証済み）
- `batch_run` は壊れているうえチャート状態を汚染する
- 銘柄切替直後は前銘柄のバーが残る → 「終値が変化するまで待つ」ゲートが必須
- 取得バーは384〜814本（チャートが読み込んだ範囲のみ）
- **リプレイは検証済みで使える**（データ側も切り詰まる）。詳細は [tooling-notes.md](tooling-notes.md) §4.5

## 10. 視覚判断（層1）の扱い — **前提ではなく仮説**

旧版では「チャートの形は数式化できない」と断定していたが、**これは誤り**。トレンドの綺麗さ＝回帰のR²/ADX、保ち合い＝ボラ収縮、支持線＝価格クラスタリングとして、いずれも定量化されている。

さらに、**チャート画像は数値から描画されたもの**なので、情報量は数値の部分集合でしかない。

→ 視覚判断は**検証対象の仮説に格下げ**。測り方は条件比較：
- **A: 数値のみ** / **B: 画像のみ** / **C: 数値＋画像** / **D: 数値＋画像＋ニュース**
- **核心は C vs A**（画像は数値に何か足すか）。差が無ければ画像は捨てる

盲検・匿名化・日付検証の装置は構築済み（[scripts/blind_sample.js](../scripts/blind_sample.js)）。1サンプルの通し実行に成功している。
